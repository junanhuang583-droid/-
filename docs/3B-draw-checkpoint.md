## 3B-0: actual rule paths
`createBasicGame` draws the P1 opening hand, then P2 opening hand, then the first player's first-turn draw. `end-turn -> beginTurn -> drawCards` draws for the incoming player before hot-seat reveal. `reveal-turn` does not draw. These are the only existing calls to drawCards.

Formal constants remain 8 opening, 4 normal turn, 5 for the second player's first turn. The existing refill combines both discards and is still explicitly a temporary rule. No fatigue is added. The collector observes existing pops/refills, never shuffles or draws again.

The formal extra normal/super evolution-stone grants are not implemented by this task. `finishOpeningDeal` injects the existing demo specials into the SHARED DECK, not players' hands. It is not a draw or hand grant. No executable merchant/skill draw is added; the result seam is available for later explicitly implemented effects.

## 3B-1: implemented result ownership
- `AcquisitionJournal` lives only inside rule execution. `drawCards` records actual ordered card occurrences, recipient, opening/turn/effect reason, requested amount, insertion-time hand index, deck sizes and actual refill immediately before each pop. Zero-success attempts are recorded but generate no flying tasks.
- `GameStore.dispatch` creates a new journal for each draft and delivers an isolated receipt to subscribers only after a successful in-memory commit. Returned errors or thrown reducers discard both draft and journal. Disk failure preserves the accepted in-memory result; flush does not redeliver it. The existing string/null command API remains compatible.
- `CardAcquisitionQueue` is a single-consumer, in-memory queue keyed by game/revision/event/occurrence. Duplicate card definitions remain separate occurrences. A high watermark prevents duplicate commit delivery, reads or rerenders from replaying consumed tasks. `takeDraws` and `takeGrants` are distinct; grant support is a result type, not a new production grant command.
- `session-runtime` wires the queue before UI observers. New-game creation supplies its real opening results; external saves discard local pending presentation. Cold restore supplies no historical receipts and does not infer draws from logs/hand sizes. Neither queue nor receipts enters BasicGameSession or any storage key.
- Existing initial/turn visual entry points now consume actual receipt cards rather than `openingCount=8`, `hand.length-openingCount` or a net before/after hand-length delta. This keeps current flight timings/targets unchanged while connecting the real data source. Grants cannot be flown from the deck accidentally.
- Each temporary flight gets only an opaque occurrence ID, not private cardId/name metadata. Receipt hand indices mean insertion-time position only, not a stable inventory ID or guaranteed current landing index after later effects.
- Existing animation epochs still cancel in-flight work. Added a post-wait/last-opening-pair guard so an old opening callback cannot consume the next game's receipts. A discarded flip clears pending cosmetic receipts without changing real cards.
