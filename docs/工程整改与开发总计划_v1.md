**基线收口定稿｜适用执行者：本聊天、Sol、后续 Codex**

本计划依据《卡牌游戏记录_v0.5》、视觉施工方案 v1.0、视觉施工补充接力 v1.1，以及用户后续明确决定。它规定工程所有权、施工顺序和验收边界，不替代原始卡牌记录，不补造规则。用户负责产品取舍和美术批准，执行者负责实现、验证和如实报告。

## 1. 当前交付与下一停止点

本批为 **B0：地图重制前工程基线整改**。代码工作包含结构整理、已确认故障修复、兼容迁移、布局统一、浏览器回归和发布保障，不是追加一层视觉补丁。原始改造起点为 `02e630d2f008b65d362089d7bcc55a157449ac62`，工作分支为 `refactor/engineering-baseline-v1`。恢复记录不是最新版凭据；开始任何接力必须读取实际 main、工作分支和未合入差异。

## 3. 工程分层和唯一所有权

### 3.1 规则层：`src/core/`

规则接收状态、卡牌目录和命令，返回结果；不得访问DOM、localStorage、浏览器事件或动画计时器。浏览器操作统一进入 `commands.ts`，由同一伤害、扣血、死亡、亡语、目标选择管线结算。

`basic-game.ts` 保留已有规则主体；`deathrattle-effects.ts` 只解析明确支持的亡语表达；`unit-targeting.ts` 负责合法目标与嘲讽；`sacrifice-placement.ts` 保持固定5格，不创建临时第6格。未知效果不得猜成相似技能，不能为了让牌能出而跳过未实现的召唤条件。

### 3.2 应用层：`src/application/`

`GameStore` 是同页唯一对局状态持有者。界面读快照；命令在草稿上执行，失败不提交，成功一次提交、一次持久化、一次通知。外部修改读快照不能改变真实状态；版本号与时间戳单调推进。保存失败保留内存对局并提示，不能伪称已经安全落盘。

存档迁移只导入同一对局未完成的旧目标队列，禁止扫描文字日志重演历史亡语。保持原v1主键与备份兼容。跨窗口使用真实storage事件，命令前检查更新；不伪造同页StorageEvent，不以定时重写存档驱动界面。现有同步降低旧窗口覆盖风险，但不是多人联机事务系统，不保证两个窗口同时操作的严格串行化。

### 3.3 界面层：`src/web/`

`app.ts` 为唯一启动入口；`game-catalog.ts` 统一目录；`session-runtime.ts` 连接状态、命令和持久化。手牌、攻击拖拽、献祭、目标弹窗只收集意图和呈现结果，不自己扣血、杀随从或排亡语队列。

显式渲染通知替代全树MutationObserver循环。使用稳定cardId/instanceId，不从名称和可见文字反推规则。旧原型外观模块可以逐步退役，但不能成为第二个规则引擎。

### 3.4 布局权威与装饰边界

`battlefield-geometry.ts` 负责变换和几何计算，`battlefield-layer.ts` 传递布局变量，`battlefield-layout.css` 负责布局表达。原型外观在低优先级 `legacy` 层。

**装饰组件只能布局自己的子元素，不得改父卡牌或随从的position、transform和锚点。** 本次斜排就是关键词样式把随从改回 `position:relative`，覆盖了合法的绝对定位。现在关键词只使用 `effects-ui.css` 中的子元素样式，不运行时注入全局几何规则。

禁止继续向大型CSS尾部堆叠 `!important` 或创建新的全局覆盖文件。需要调整几何，应修改拥有该参数的模块，并更新对应断言。

### 3.5 资产、构建、版本

保留战场12分块与结束回合8分块的构建重建、字节数和SHA校验。文件头正确不等于可解码，生产页面必须验证实际图片解码。图片失败时，结束回合保留可见文字与真实button，不再出现透明但能点的控件。

依赖使用精确版本和lock，安装执行 `npm ci`。构建生成版本化完整离线壳，包括index及其依赖资源。验收证据归档源码ZIP、生产包、源提交、截图和JSON结果。不得只凭临时会话里有一张图片，就写“资产已入库”。

## 4. 坐标与响应式契约

设计平面为1152×648，背景及固定结构共同使用一个cover变换。显式提供worldToScreen、screenToWorld、可视世界矩形，禁止背景cover而控件另用contain。设计平面在变换前必须仍为1152×648，不得被遗留min-width/aspect-ratio二次缩放。

固定机关读取 `FIXED_SOCKETS`，后续外壳、核心、牌堆和遮挡边界必须共用图片坐标。当前值是工程过渡接口，V2出图前仍须共同确认，不是已批准的新地图。

英雄、战线、收起手牌属于可视区域玩法布局，可在共同世界平面内响应裁切。`gameplayGeometry()` 集中计算单位尺寸、步距与英雄间距，不单靠百分比位置。两排的所有单位必须水平对齐；1～5只稀疏逻辑槽也必须在空闲态紧凑居中；召唤态返回5个真实逻辑目标。

验收横屏：1152×648、1536×691、1400×500、896×414、740×360、1920×1080。竖屏只作为菜单/旋转过渡，超出已验收比例须另测。未来若英雄也要固定建筑外壳，需要先重定安全区，不能把响应式英雄直接塞进固定画死的槽。

## 7. 后续总路线与交付门槛

### 阶段B0：工程基线（本批）

输出源码、依赖锁、规则回归、完整页面浏览器测试、截图、验收报告和本总计划。结束时停在地图重制之前。测试出现失败就修正原因，不降低断言以换取通过。

### 阶段V2：0-7.3 左右一体化战场

**输入：** 获准战场母图、已定卡背、结束回合设计、牌库概念及共同坐标规格。缺少可读取的正式图时须明确列出，不能凭记忆替代。

**先确认：** 原图保留区、横屏裁切安全区、左右插槽尺寸、核心运动范围、数字区和前景压边。之后由用户明确授权出图。左右一起设计，不拆成两次独立美术施工。

**固定环境：** 左侧空牌槽、承托与金属连接、空铭牌；右侧完整四角外壳、石槽与墙体连接。主体环境尽量保留。**活动内容：** 结束回合面板、真实文字、卡背牌堆、准确数字。**前景层：** 必要的槽口、压边、卡扣。

背景不得重复画一个亮着的完整按钮，也不得把牌堆和数量画死。按下时外壳不动，只有核心活动；牌必须能脱离槽口。卡背直接复用定版。

**通过标准：** 左右材质、透视、环境光协调；无CSS黑矩形、缺角、背景残片或重复按钮；机关可用/禁用/按压正常；空槽和4/3/2/1/0牌堆状态成立；所有固定接口在验收横屏比例中一致，不挤战线。这个阶段通过前不宣称已达到一体感。

### 阶段D：0-7.4 动态表现

抽牌接收真实规则事件，不在动画中写死4张；处理初始8、通常4、后手首次5、技能抽牌及循环。逐张背面朝上从左槽到对应手牌/隐藏区，热座交接不泄露对手正面。准确数量由状态提供，牌堆厚度仅作抽象。

完善机关按压、受击和有限环境粒子，保留减少动态效果模式。规则先可靠提交，动画取消、刷新、切后台不得重复摸牌、丢牌或锁死控件。牌库静态层数在V2已经正确，本阶段只完善逐张运动与过渡，避免重复施工。

### 阶段F：0-7.5 战场收口

只微调已批准材质、亮度、阴影和工具入口，不借精修重设计徽记或背景。验证长手牌、连续回合、暂停返回、离线、升级、PC浏览器和真实手机横屏/PWA。真实硬件结果与CI结果分开列出。

### 卡牌正面A～H

A骨架 → B卡框分层 → C五套基础母版 → D品质/稀有度 → E手牌最终表现 → F战场单位 → G品质动态 → H材质精修。任务名称必须带“卡牌正面”前缀，避免与战场D/F混淆。

先用少量代表牌覆盖长名称、多技能、多属性、动态数值，再批量套用。原型框图不是最终组件完成证据。每步写清输入资产、输出组件、保留项、禁止项与截图场景。

### 玩法补齐和PC延续

按第6节矩阵补进化、装备、场景、系列与状态例外；先规则测试、再UI。AI只能选择合法命令，不能直接改存档。后续Codex桌面封装不得复制第二份规则引擎。联网仍非当前范围。

## 8. 强制验收与发布流程

本地或可信CI统一执行：

```sh
npm ci
npm run check
npx playwright install --with-deps chromium
npm run test:browser
```

规则测试覆盖链式亡语、石化抑制、守护与扣血区别、嘲讽、重复/过期/无目标、满场献祭、失败命令回滚、备份与迁移。浏览器必须运行生产构建，不使用孤立按钮页充当整局验收。

布局检查必须遍历每一只实际随从：水平中心、行内边界、双方半场、英雄间距、单位互不重叠、真实命中区域；再测1～5只稀疏槽与召唤态5槽。只检查第一只单位或x递增不合格。两档手机比例增加真实浏览器触控事件拖到最右逻辑槽，不能只派发DOM click冒充拖拽。

持久化覆盖目标选择中刷新、热座、真实storage跨标签页、保存失败、完整壳离线启动、新壳安装失败保留旧壳、旧哈希资源被服务器删除后的缓存回退。至少有正常动画模式中途刷新测试，不只测减少动态模式。

流水线顺序：**工程验收 → 生产构建 → Pages部署 → 线上浏览器检查。** 线上检查核对sourceCommit、实际图片解码、4档横屏铺满、10只随从、按钮命中和回合推进。任何一段失败不得标为交付成功。

证据包必须包含测试源SHA、原始JSON结果、关键截图、可恢复源码和生产包。截图要实际打开检查，不能因为文件已生成就写“肉眼验收无误”。CI触屏模拟不等于Android/iOS硬件实测。

## 9. 接力任务单和执行纪律

后续每次施工采用同一任务单：**目标；允许修改的模块；禁止触及的内容；输入资产；验收用例；交付物；下一停止点。** 一个任务包包含实现与复测，不为每个参数反复向用户索取授权，但不得扩大到另一个阶段。

开始前读本计划、最新验收报告、AGENTS和实际Git状态。命令只从唯一入口写状态；UI不结算规则；装饰不改父几何；未知能力不伪装可用；出图单独授权。先分支测试再合入，不向main连续推未验收的试错图。

报告写清本次改了什么、什么没有做、通过/失败数、源码版本、证据路径、网站是否已更新。用户否决效果后立即标记旧结论作废。严禁把“已计划”“已生成文件”“构建通过”写成“实机通过”。

发生中断，检查点保存分支、SHA、未提交内容、失败用例、证据路径与下一步；恢复先读仓库，不依赖模型自述。不得force覆盖其他工作者变更。

## 10. 已知边界、维护和恢复

原型卡牌样式仍在legacy层，随着A～H替换逐步删减；核心规则主体也不是为了重构而全部重写。本批解决关键所有权、重复结算、布局和验收问题，不声称所有历史代码已经理想化。

依赖审计留存原始JSON。当前审计提示Vitest及其mocker开发测试依赖涉及同一moderate公告；不得把测试通过说成安全审计零告警，也不运行破坏性的 `npm audit fix --force`。后续专门升级测试工具链并复跑全套，开发/测试服务不对公网开放。

多单位同时死亡通用调度、全部卡牌能力、真实设备PWA安装、严格多窗口并发、竖屏完整对战、桌面封装均有明确后续范围。范围外问题不伪装完成，也不为一次工程验收无止境扩展任务。

合入前读最新main并比较差异，普通快进或常规合并，不force。回退用对应提交的明确revert及回归，不手工再叠覆盖CSS。只清本应用壳缓存，不清对局localStorage或其他应用缓存。原图与定版卡背须建立可靠资产归档，尚未入库的批准图片必须在V2准备时核实并归档。
