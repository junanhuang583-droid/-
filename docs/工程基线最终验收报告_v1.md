## 2. 本批核心改造结果

### 2.1 单一游戏状态所有权

- `src/application/game-store.ts` 成为同页状态所有者。
- 浏览器 UI 只读取快照并提交命令，不再各自从 localStorage 读取后直接改血量、死亡、目标队列。
- 命令先在草稿状态执行；失败不提交，成功才统一提交、持久化和通知。
- 跨标签页同步使用真实 `storage` 事件；同页模块依赖 store 订阅，不再伪造 StorageEvent。
- 存储失败不会回滚已经合法完成的内存操作，并明确提示当前对局只在内存中。

### 2.2 统一规则结算管线

- 普通攻击、定点伤害、死亡、亡语等不再由 UI 维护第二套死亡算法。
- 修复已实际复现的链式问题：火山之灵定点伤害击杀潮汐鱼人后，潮汐鱼人的亡语衍生物会继续产生。
- 目标弹窗从规则层取得合法目标，不靠界面自己猜目标。
- 献祭回到固定五格模型，不再借临时第六格完成交换。
- 未实现的进化石系列条件继续阻止非法绕过，不用“免费可用”掩盖缺功能。

### 2.3 战场几何真正统一

- 世界设计平面固定为 `1152×648`。
- 背景与固定世界对象使用同一套 cover 变换，几何计算集中在 `battlefield-geometry.ts` / `battlefield-layer.ts` / `battlefield-layout.css`。
- 修复旧 CSS `max-width/max-height` 先把 1152×648 本地平面缩小、随后 JS transform 再缩放一次的“双重缩放”问题。
- 新增浏览器回归，明确验证横屏 740×360 时元素的本地 `offsetWidth/offsetHeight` 仍为 `1152×648`，防止未来重新引入该错误。
- 已否决的 0-7.2B CSS 黑色假凹槽和镜像补角不属于新基线，不得恢复。

### 2.4 前端模块与 CSS 收敛

- `src/web/app.ts` 成为统一启动入口。
- 新增 `session-runtime.ts`、`game-catalog.ts`、`view-events.ts` 等边界模块。
- 删除多批未使用或重复的旧视觉/行为模块，包括原 `foundation-cd.css` 大型叠加文件、旧 `foundation-ab.ts`、`tabletop-ui`、`polish-v2`、`battlefield-preview` 等。
- `battlefield-layout.css` 是战场几何权威；旧原型视觉保留在低优先级 `legacy` cascade layer，只能提供皮肤，不得反向控制战场几何。
- 结束回合当前完整 WebP 只是地图 V2 前的过渡按钮；图片缺失或解码失败时会恢复可见文字按钮，避免再次出现“透明但能点”。

### 2.5 存档、PWA 和发布

- 继续兼容原 v1 主存档键，并增加主存档校验与备份回退。
- 构建时重建并校验战场、结束回合二进制资产，保留字节数与 SHA 检查。
- Service Worker 改为构建阶段生成完整离线壳；新壳安装失败时保留旧壳，不清空其他应用缓存，不删除游戏 localStorage。
- Pages 主分支流程改为：工程验收 → 构建 → 部署 → 已发布站点 smoke check。构建成功不再自动等于发布效果验收。
- 依赖使用 lockfile 固定。

## 5. 已知维护项，不阻塞本批验收

- `npm ci` 当前报告 2 个 moderate 级依赖审计提示。当前依赖均属于开发/构建工具链，工程测试和发布构建通过；后续升级 Playwright/Vite 等工具时应重新审计，不能为了消警告直接使用破坏性 `npm audit fix --force`。
- 旧视觉 CSS 中仍存在低优先级 legacy 原型定义。它们不再拥有战场几何权；未来卡牌正面 A～H 完成后，应随着旧原型皮肤退役继续删减，而不是再在末尾覆盖一层。
- 多单位同时死亡的完整“由归属方选择亡语顺序”等通用调度尚未完成，必须按正式规则继续实现，不能从当前部分亡语支持推断为完整支持。

## 6. 下一阶段唯一入口：战场 V2

下一步不是继续修 CSS 石墙，也不是马上写抽牌动画，而是先完成 **0-7.3 左右一体化战场 V2 的精确制作规格**：

1. 在 1152×648 authored plane 上标出原图保留区和主要横屏裁切安全区。
2. 左右同时确定：左侧空牌库槽、承托/压边/数字位置；右侧完整四角机关外壳、嵌槽、活动核心范围。
3. 明确哪些结构进入固定背景、哪些要独立活动、哪些必须作为前景遮挡层。
4. 背景中不画死实际牌堆、精确数量或亮着的结束回合核心。
5. 用户明确说“生成/出图”后才允许调用图片生成；代码授权不能替代图片授权。
6. 左右共同定稿后一次接入，不再先做右边又返工左边。

地图 V2 接入完成后才进入 0-7.4 动态表现：真实抽牌事件驱动的逐张飞牌、机关按压、有限粒子/环境反馈等。
